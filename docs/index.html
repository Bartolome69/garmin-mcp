How technical is this, honestly?

There's nothing to double-click. You paste one line into Terminal, press Return, and answer what it asks. If you can follow a recipe, you can do this. Nothing here can break your Mac, and every step undoes cleanly.

Setting it up

  1. 01

    Open Terminal

    Cmd + Space, type Terminal, press Return. A window with a blinking cursor appears. It's just somewhere to paste instructions.

  2. 02

    Paste this, press Return

    Terminal 
    $ curl -fsSL https://raw.githubusercontent.com/Bartolome69/garmin-mcp/main/scripts/bootstrap.sh | bash

    Downloads the code, sets up Python, gets everything ready. Two or three minutes the first time. Text will scroll past — let it.

  3. 03

    Sign in to Garmin

    It asks for your email, your password, and a code if you use two-factor.

    Your password won't appear as you type. No dots, no stars, nothing at all. That's deliberate, not a frozen screen — type it and press Return.

    It goes straight to Garmin and is never written to disk. Only the session token comes back, saved in a file only you can read.

  4. 04

    Quit Claude, run one more line

    Claude Desktop rewrites its own settings when it closes, so it has to be properly shut. Cmd + Q — closing the window isn't enough. Then, back in Terminal:

    Terminal 
    $ ~/garmin-mcp/scripts/install-claude-desktop.sh

    If Claude is still open it says so and changes nothing, so you can't get this wrong. Skip it entirely if step 02 already said "Done".

  5. 05

    Open Claude and ask

    Start a new chat. If it comes back with your real numbers, you're done.

    • "What did my last run look like? Break it down by kilometre."
    • "Has my resting heart rate moved over the past two weeks?"
    • "Am I running everything at the same effort? Check my last ten runs."
    • "Build me a threshold session for Thursday and put it on my watch."

Make it a coach, not a lookup tool

Claude will answer questions about your data straight away. It gets sharper if you tell it how to work first.

Nothing to fill in. Paste it in and it interviews you — reading your personal bests back from Garmin to check they're current, asking how you feel against them, what you're aiming at next, and what your real max heart rate is. Four questions, one message.

Once you've answered, paste your answers underneath it and later chats can skip the interview.

Training prompt 
You have access to my Garmin Connect account through the `garmin` MCP server. Be my running coach and training analyst.

Start with a short interview. Before you ask me anything, call get_profile and get_activities, so your questions come from evidence rather than blind. Then ask me, in a single message:

1. My personal bests. Read back what Garmin has and ask which are still right — it only knows races I ran wearing the watch, so some may be missing, and some may be years old.
2. How I feel against those bests right now: still in that shape, some way off it, or coming back from a break.
3. What distance I want to focus on next, and whether there's a race and a date.
4. My max heart rate, and whether that's from a real test or Garmin's age-based guess. Every heart-rate zone you'll see depends on that number, so if it's a guess, treat zone percentages with suspicion and lean on pace instead.

Group all of it into one message — don't spread it across five turns. Alongside the questions, tell me what you've already worked out from my recent training, and ask me what you've got wrong. Don't prescribe anything until I've answered.

Then, working with me:

- Always pull the data before forming a view. get_activities for recent sessions, get_activity_details for splits and heart-rate zones inside one run, get_daily_summary for resting heart rate and stress. Don't ask me for numbers you can look up, and don't reason from memory of earlier messages.
- Prescribe from what I can do now, not from my PBs.
- Be direct about what the data does and doesn't support. If three runs isn't enough to call a trend, say so rather than producing a confident narrative.
- Notice the boring things that matter: pace drifting up at the same heart rate, cadence dropping late in runs, every run landing in the same narrow effort band, resting heart rate creeping.
- If get_sleep_data comes back empty several nights running, I don't wear the watch overnight. Say so once, then stop building on recovery metrics I don't have.
- When I ask for a session, build it with create_workout and schedule it with schedule_workout so it reaches my watch. Show me the structure and wait for me to confirm — those write to my real account.
- Prefer one specific, well-argued recommendation to a menu of options.
- You're not a doctor or physio. If something looks like an injury or health question, say so plainly and stop there.

When it doesn't work

It mentioned being rate limited, or a 429

The most common one, and it isn't your password. Garmin blocks sign-ins by network address before it ever checks your credentials. Office wifi, university networks and VPNs get hit hardest, because everyone on them shares a single address.

The fix that works: turn off wifi, tether to your phone's hotspot, run the command again. You only need the clean connection for that one sign-in — after that the saved session does the work.

Claude can't find any Garmin tools

First, ask it what's wrong. Paste this into Terminal — it checks every link in the chain and names the broken one:

Terminal 
$ ~/garmin-mcp/scripts/doctor.sh

Nearly always it's step 04. Claude Desktop must be fully quit (Cmd + Q) when the settings are written, or it overwrites them with its own copy on the way out and the connection quietly vanishes.

One more thing that catches people: an existing chat keeps talking to the server it started with. After fixing anything, start a new chat rather than continuing the old one.

Quit it properly, run the step 04 command again, reopen. A fresh chat helps too.

It failed while installing, mentioning Rust, OpenSSL or a compiler

Your macOS is too old. The floor is macOS 10.15 (Catalina), and it's a hard one — the Python this uses simply won't start below it. Updating macOS is the only fix. Any Mac from 2012 onwards can run Catalina.

Check it under the Apple menu → About This Mac. Updating macOS fixes it.

It wants a code I never received

That's Garmin's two-factor. The code goes to the email on your Garmin account, or to your authenticator app — check spam if it's email. Run the command again once you have it; retrying costs nothing.

It says there's no sleep data

Your watch wasn't on your wrist overnight, or hasn't synced. Sleep, HRV and overnight body battery only exist if you wear it while asleep. Runs, splits and heart rate all work regardless.

My data looks out of date

Claude reads Garmin Connect, not the watch itself. Open the Garmin Connect app on your phone, let it sync, ask again.

How do I remove it?

Delete the garmin-mcp folder in your home directory and the hidden .garmin-mcp folder beside it — that's the saved session gone. Then drop the "garmin" entry from Claude Desktop's settings. Nothing is installed anywhere else, and nothing changes on Garmin's side.

Somewhere other than Claude Desktop

None of this is Claude-specific underneath — it speaks MCP, an open standard. Anything that can start a local MCP server will run it: Claude Code, Cursor, VS Code, Zed, Windsurf. Point them at python -m garmin_mcp over stdio; the repo has the config.

ChatGPT is the exception, and it's a hard no. Its connectors need a public web address to call, because ChatGPT runs on OpenAI's servers and can't start a program on your laptop. No setting changes that, and no amount of fiddling will get this working there.

What it can and can't touch

Everything runs on your own Mac. Your data goes nowhere except between your computer and Garmin, and your password is never stored.

Reading is unrestricted: daily summaries, sleep, activities, splits, heart-rate zones. Writing is limited to two things by design — creating a workout, and putting it on a date. There is no tool that deletes or overwrites anything in your Garmin account. The worst it can do is leave you a session you didn't want, which you bin in the Garmin app like any other.
